# Mission 03: Locked out

A second intrusion happened on my workstation (WKS-L58): I lost my own access, and the job is to get back in, work out how the attacker got there first, and recover what they staged. Most of this mission happens off the workstation — on my own attack machine over Tailscale — because scanning, SMB enumeration and credential decryption aren't things Sentinel can see. Only the pieces that touch WKS-L58 itself (the RDP reconnection, the lockout-era failed logons, the anonymous SMB access) will show up in my Sentinel workspace.

**Status: all five steps complete, and every CTFd flag for this mission submitted.** Host confirmed (`10.50.0.58`, reached via a Tailscale subnet route into `hamilton.corp`), port scan done (SMB 445 + RDP 3389 open). Widening the scan to the whole `10.50.0.0/24` subnet found a sibling host (`10.50.0.50`) where `Public` is anonymously readable — recovered a low-privilege domain account (`training01`) from it (`HAM{anon_smb_seat50}`, "First foothold"). Found the domain controller (`10.50.0.10`, identified by behavioral fingerprinting since its AD ports are firewalled off this path), pulled SYSVOL (17 near-identical GPOs, one per workstation seat), and decrypted a GPP `cpassword` for a local account (`svc_deploy`) — each seat's own password independently generated, confirmed by decrypting two different seats' values (`HAM{gpp_cpassword_seat58}`, "The climax"). Diagnosed and confirmed (both client-side and via Sentinel's `STATUS_NO_SUCH_USER` substatus on 22 failed logons) that `svc_deploy` had to be addressed as a local account (`.\svc_deploy`), not `HAMILTON\svc_deploy` — logged back into the real desktop (`HAM{admin_rdp_seat58}`, "Privileged return"). Recovered all three staged desktop artifacts: the proof flag (`HAM{desktop_proof_seat58}`), a new Sentinel credential (used to resume monitoring), and a staged data cache (`employees.csv`, 4 rows of employee PII) assessed for breach-notification duties in the case file. A follow-on check of what the decrypted `svc_deploy` credential could reach turned up a second, equally-anonymous `Public` share on WKS-L58 itself (not just `.50`'s), plus a clear demonstration of Windows' Remote UAC token filtering (admin shares denied over SMB, full access over interactive RDP) — both written up in `notes.md`.

**Handling note:** this mission surfaces a real decrypted credential and a real Sentinel password. Neither goes into this public repo in plaintext — see the redaction note in `notes.md` and `case-file.md`. The Sentinel credential gets rotated before it's used for anything beyond proving access.
